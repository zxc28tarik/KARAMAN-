# Asset contracts

These are the shared rules every agent builds against. A contract change is a Gate A decision: the art-director proposes it, the integrator approves it, and this file is updated **before** any asset uses the new rule. The values below were measured from the code on 2026-10-10. If code and this file disagree, report it; don't silently pick one.

## 1. Space, scale and camera
| Quantity | Value | Source of truth |
| --- | --- | --- |
| Render pipeline | Built-in (no URP/HDRP), custom shaders in `Assets/Resources/Shaders` | Packages/manifest.json |
| View | 4:3, orthographic size 5.4, so 14.4 × 10.8 world units | `GameView.cs` |
| Game-pixel grid | **360 × 270** game pixels; 1 game px = **0.04 units**; **1 unit = 25 game px** | `PixelPipeline.Width/Height/PixelSize` |
| Internal supersample | 4×, so the world RT is 1440 × 1080 before downsampling | `PixelPipeline.Supersample` |
| Review render | 1440 × 1080 (each game px = 4×4 screen px) | `GameView.RenderWidth/Height` |
| Camera | x follows the player, clamped to 4..49; y = −0.4 (`GroundCameraY`); z = −10 | `GameRoot.cs` |
| Ground | main floor y = −2.25; zone length 57 units; one-way platforms per `ZoneDefinition.surfaces` | `GameTypes.cs` |
| Hero height | idle hero = **20–26 % of view height** (≈ 62 game px, ≈ 2.5 units). Locked; see DESIGN_CONSTRAINTS. | `BuildTools.VerifyPresentation` |
| Axes | +x = right, +y = up. Actors face with `face = ±1`; sprites mirror via negative x scale only | `PixelCharacter` |

Rules:
- **No mixels.** Everything in the world lands on the 720×540 grid through `PixelPipeline`. Only exception: HD playable characters (`Resources/Characters/hd/*`, user decision 1a), drawn at screen resolution. Don't put sprites at other pixel densities on the UI layer to fake detail, and don't scale pixel sprites by non-integer factors.
- **Characters are single-piece frames** (one SpriteRenderer per actor, verified). A frame is never scaled, rotated or split into parts at runtime. Its position snaps to the game-pixel grid, and size differences (captain 1.09, guards 0.98) are drawn into the art.
- Planted feet are stride-locked: frame advance follows distance travelled, and foot drift at frame changes is **< 1 game px (0.04 u)** (verified, measured 0.000001 u).
- Hit line: from the body at hand height to the blade tip of the current frame (`PixelCharacter.StrikeRoot` → `BladeTip`).

## 3. Files, folders and naming
| Kind | Location | Format / import |
| --- | --- | --- |
| AI-painted source art (immutable) | `Assets/Resources/Art/<kebab-name>.png` | PNG RGBA, uncompressed, mipmaps off, NPOT none, bilinear, max 4096 (`ArtValidation.PrepareArt`). **Never edit, re-save or resample these files.** SHA-256 list in `Docs/QA.md`. Derived versions go to new files. |
| Pixel sprite sheets | `Assets/Resources/Characters/<variant>.png` + `<variant>.json` | Generated by `Tools/pixel_characters.py`; never hand-edited. Point filter, uncompressed, no mipmaps. |
| New environment / prop sheets | `Assets/Resources/Environment/<zone-or-set>-<name>.png` (+ `.json` if sliced by data) | Same import rules as pixel sheets |
| VFX sprites / shaders | `Assets/Resources/FX/…`, `Assets/Resources/Shaders/<Name>.shader` | Shader names `Karamani/<Name>` |
| Runtime C# | `Assets/Scripts/<PascalCase>.cs`, namespace `KaramaniReborn` | One main type per file. Match existing style: compact, Turkish comments. |
| Editor C# | `Assets/Editor/<PascalCase>.cs`, namespace `KaramaniReborn.Editor` | Verify/capture entry points live in `BuildTools` |
| Generators / tools | `Tools/<snake_or_kebab>.py|.ps1|.cjs` | Python runs with `python -I`; deps numpy + Pillow only, unless the user approves more |
| Review evidence | `Review/…` (see BUILD_AND_CAPTURE.md) | PNG; never committed as "source" |
| Specs / reviews | `Docs/specs/<slice>-<topic>.md`, `Review/reviews/<date>-<slice>-<agent>.md`, `Review/gates/<slice>.md` | Markdown |

Every new asset under `Assets/` gets its `.meta` from Unity. Don't hand-write `.meta` files, except to copy settings from an existing sibling when Unity can't run.

## 4. Pixel sprite-sheet format (`<variant>.json`)
Produced by `Tools/pixel_characters.py`, consumed by `Assets/Scripts/PixelCharacter.cs`. Variants: hero, duelist, shield, archer, captain, ghoul (= `EnemyRole` names in lower case). Import settings are enforced by `Assets/Editor/CharacterSheetImport.cs`: point filter, uncompressed, no mipmaps, readable.
```
frameWidth, frameHeight : 128, 128       game px per frame
pivotX, pivotY          : 64, 40         pivot = ground contact point, measured from the frame's bottom-left
columns                 : 16             frames laid out row-major, top row first
pixelsPerUnit           : 25.0           must equal 1 / PixelPipeline.PixelSize
frames[i]  : { bladeRoot:[x,y], bladeTip:[x,y], plantedN:x|-999, plantedF:x|-999 }
             pivot-relative game px, +x = facing direction, +y = up; -999 = foot not planted
clips[j]   : { name, start, count, bounds:[t0..tN] (normalised frame time boundaries; empty = uniform), stride (game px per locomotion cycle; 0 = none) }
```
Unity sprite pivot = (pivotX / frameWidth, pivotY / frameHeight) = (0.5, 0.3125).

## 5. Animation state contract
Gameplay state (`ActionState` in `GameTypes.cs`) → required clips. The animator owns clip content; the gameplay-engineer owns the state machine and the timing windows (`duration`, hit frames, parry window). A clip's **active frames must line up with the gameplay hit window**. When either side changes timing, both sides update this table.

| ActionState | Clips (hero sheet names) | Notes |
| --- | --- | --- |
| Idle | `idle` (6) | loop |
| Move | `walk` (8, stride 34), `run` (8, stride 50), `skid` (2) | the frame advances by distance walked (stride), not by time |
| Jump / Fall | `rise` (2), `apex` (1), `fall` (2), `land` (2), `flip` (6, double jump) | |
| Light | `light1`, `light2`, `light3` (7 each, timed `bounds`) | 3-hit buffered combo |
| Heavy | `heavy` (10, timed) | breaks shield guard |
| Light/Heavy while airborne + down | `dive` (3) | downward strike, bounce on hit |
| Block / Parry | `block` (2), `parry` (2) | riposte uses the `light*` clips |
| Dodge | `roll` (6), `backdash` (3) | i-frames are owned by gameplay |
| Hurt / Dead | `hurt` (3), `dead` (5) | |
| Heal / Spirit / Shoot | `heal` (6), `spirit` (4), `shoot` (5) | spirit = wolf dash (Q) |
| Hang / Climb | `hang` (2), `climb` (6) | ledge grab |

Enemy variants carry a subset (see `build()` in `pixel_characters.py`): no flip, roll, backdash, spirit, dive, heal, skid, hang, climb, light2, light3 or parry; `heavy` only for captain.

## 6. Colour and light
- Each zone has a 12-tone main ramp plus shared accent ramps: skin, crimson cloth/blood, brass/gold, fire, wood. That gives 37 colours (`PixelLook.For`). Uncoloured pixels stay on the zone ramp; only genuinely coloured surfaces switch to accents.
- Character material ramps have 5 tones (0 outline, 1 shadow, 2 mid, 3 light, 4 highlight) and are defined in `pixel_characters.py` `BASE_RAMPS`. New materials add a ramp there and must stay within the zone + accent palette after quantisation.
- Key light for characters comes from the upper right, toward the camera (`LIGHT = (.38, .62, .68)`). Environment lighting must not contradict it within a zone.
